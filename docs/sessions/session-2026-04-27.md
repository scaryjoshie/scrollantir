## Operational reference

### Hetzner VM access
```bash
ssh orch                               # ~/.ssh/config alias for 178.104.253.30
sudo systemctl status scrollantir-runtime
sudo docker compose -f /opt/scrollantir/repo/runtime/compose.yaml ps
sudo docker exec scrollantir-postgres-1 psql -U scrollantir -d scrollantir
```

`/opt/scrollantir/repo/runtime/.env` (mode 600, root-only) contains all
the prod secrets. `$ chars in DASHBOARD_BCRYPT must be doubled (`$$`)
for compose interpolation; documented in `.env.example`.

### Public endpoints
- **`https://ingest.178-104-253-30.nip.io`** — clients POST events.
  Functions: `accept_event`, `accept_prompt_answer`, `pending_prompts`.
  Header: `Content-Profile: ingest_api` (or omit; ingest_api is default
  in PGRST_DB_SCHEMAS).

  for the dashboard. Basic auth (`josh:<password>`).

## Schema reference

10 tables in 4 schemas. Source-of-truth: `runtime/db/schemas/30_tables.sql`.

**public** (events, derived data, agent-authored):
- `events` — raw events. `(start_ts, end_ts)` canonical; `device` GENERATED from `split_part(source, '.', 1)` and FK'd to `devices`. `duration_s` GENERATED. Source CHECK regex.
- `derived_events` — computed by derivers. `source` is `<kind>/<version>` (regex `^[a-z][a-z0-9_]*/v[1-9][0-9]*$`).
- `devices` — TEXT id PK; `kind ∈ {physical, service}`. Seeded: phone, mac, cloud, prompt.
- `prompts` — `derived_at` for LLM-deriver lifecycle. Lifecycle CHECKs.
- `reports`, `annotations`, `places`, `source_tags`.

**private**:
- `tokens` — sha256 hash + prefix; `octet_length(token_hash) = 32` CHECK.
- `ingest_rate_limit` — per-device fixed window.

**ingest_api** (anon EXECUTE):
- `accept_event(p_token, p_id, p_source, p_start_ts, p_duration_s, p_data)` — token validate → source-prefix check → rate-limit peek → INSERT … ON CONFLICT DO NOTHING → charge budget.
- `accept_prompt_answer(p_token, p_prompt_id, p_answer_event_id, p_data)` — atomic UPDATE prompts + INSERT answer event with source `prompt.<kind>`.
- `pending_prompts(p_token)` — unanswered + unexpired prompts.

**agent_api** — empty; populated in commit #5 (deferred).

Key triggers / functions:
- `set_updated_at()` — BEFORE UPDATE on places, reports, annotations.
- pgcrypto's `digest()` used by ingest_api functions for token hashing.
- `REVOKE EXECUTE ON ALL FUNCTIONS IN SCHEMA public FROM PUBLIC` defense-in-depth (audit fix).

## Viz lessons

The dashboard's Raw view uses vis-timeline with one swim lane per
source. ActivityWatch's web UI uses the same library and is widely
considered smooth/clean; ours feels less so. The functional surface
is similar; the polish difference comes down to:

1. **Tooltip configuration** — AW: `followMouse: true, delay: 0,
   overflowMethod: 'flip'`. Makes hover feel instant + glued to
   cursor. Default vis-timeline tooltip pops at fixed offset with
   delay. Not yet applied here.
2. **`horizontalScroll: true`** — natural Mac trackpad pan instead
   of scroll-zoom-only.
3. **`keyboard: { enabled: true }`** — keyboard nav. Nice polish.
4. **`zoomMin: 60_000`** (1 min) instead of 1000 (1 second) — caps
   how far you can zoom in. Mine zooms too tight, feels weird.
5. **Pre-filter sub-1s events** — AW filters `duration > 1` before
   render to remove flicker. Live data shows 24% of `mac.zen.tab`
   events are sub-second flicker that adds visual noise.
6. **`setData()` over destroy/recreate** — AW creates the timeline
   once and mutates DataSets. Mine destroys + recreates on every
   data change. Heavier but only matters on date change / refetch.

`RawTimeline.tsx` has a header comment block documenting the public
contract any timeline implementation must honor — modular boundary
for swapping vis-timeline if needed.

## Things to know that aren't obvious from code

- **`$` chars in bcrypt hashes** must be doubled in compose `.env`
  files because compose interpolates `$VAR` references in env values.
  E.g. `DASHBOARD_BCRYPT=$$2a$$14$$...`. Documented in
  `runtime/.env.example`.

- **PostgREST routes `/rpc/<name>` to the FIRST schema in
  `PGRST_DB_SCHEMAS`** as default. We removed `public` from the list
  (audit fix #1) so pgcrypto/earthdistance functions aren't
  callable anonymously — `gen_salt('bf', 12)` is a CPU-tunable DoS
  amplifier. Clients reaching ingest_api don't need
  `Content-Profile: ingest_api` header anymore (it became default)
  but the header still works.

- **`postgrest-dashboard` uses `anon=user_role`** so unauthenticated-
  from-PostgREST's-perspective requests fall through to user_role,
  which has SELECT on public.*. Caddy's basic_auth is the only
  authentication layer for that endpoint.

- **`compose.override.yaml` is gitignored** and only present on the
  Mac. Production never has it. Local dev uses it to expose
  postgres on host port 55432 for the admin CLI.

- **`prompt.<kind>` events** require a `prompt` device in `devices`
  table (kind=service). Seeded at init. Without this row,
  accept_prompt_answer would fail the FK on the generated `device`
  column.

- **Sources MUST be `<device>.<rest>`** — the FK on
  `events.device` (generated from `split_part(source, '.', 1)`)
  enforces this. Bare `youtube.shorts` (legacy) is rejected. The
  Android client prefixes `phone.` at the wire boundary in
  `IngestClient.postEvent`, NOT at emit time, to avoid cascading
  ~30 edits through DAO @Query strings.

- **ScreenWatcher bootstraps from PowerManager + KeyguardManager**
  on register (commits b58c7ef + e570a55). Without this, every
  service start while screen-on/unlocked dropped the in-flight
  span until a full off→on cycle.

- **The dashboard's basic-auth password** lives in two places: the
  Hetzner `runtime/.env` as a bcrypt hash (DASHBOARD_BCRYPT, with
  doubled `$`), and the local `dashboard/.env.local` as plaintext
  (VITE_DASHBOARD_PASSWORD). Generate a new hash via
  `docker run --rm caddy:2-alpine caddy hash-password --plaintext '<pw>'`.
