## What is NOT shipped (open work)

In rough priority order — none of these is blocking, all are
optional improvements:

1. **`is_open` indicator** on currently-active visits (so the
   timeline shows "ongoing" rather than "ended at 4:23 PM" while you
   haven't actually left).
2. **Confidence ⚠ indicator** in the dashboard — surface
   `provenance.match_confidence < 0.7` or `p95_accuracy_m > 30`
   visits as "low-trust" so the user can override.
3. **Topic chunks** — render-side composition over `events` that
   shows "you spent 1h on cmux at Tech Institute" inside a visit's
   detail panel. The `lookups.topicChunks` provider in
   `dashboard/src/features/today/lookups.tsx` is wired and defaults
   to `[]`.
4. **Per-visit name override** — you can rename a place row, but
   building 275854338 (parking garage / SPAC / The Garage co-working,
   all stacked) cannot be differentiated by visit context. Either a
   `data.display_name_override` field on visits OR shipping topic
   chunks (which would let app-usage signal differentiate "working
   at The Garage" from "at the gym").
5. **`v_active_mask` view** — independent from /today; ships when
   /summary work begins.
6. **Multi-building highlight overlay** — current behavior
   highlights only the selected visit's building. A "where I was
   today" overlay highlighting every visited building is doable.
7. **`phone.location.coarse` tier-2 source** — the GPS-noise session
   contemplates a relaxed indoor tier (non-attested, accuracy < 25m)
   as a separate source. Not collected. Deriver would extend
   `INPUTS` and weight differently in centroid math.
8. **`deploy.sh` doesn't actually work** — server has no `.git`. We
   `rsync` from local. Either fix the script or document the rsync
   pattern.
9. **Integration tests against a real Postgres** — pipeline tests
   use mocked psycopg. Window-boundary + late-arriving-GPS replay
   cases (tests g + h in the plan doc) need pytest-postgresql or
   testcontainers.

## Operational facts you'll need

- Server: `ssh orch` (Hetzner CAX11). Code at
  `/opt/scrollantir/repo/runtime/`, env at `runtime/.env` (mode
  0600, root-owned). `.env` includes `MAPBOX_API_TOKEN` (same `pk.*`
  value the dashboard uses via `VITE_MAPBOX_TOKEN`) and `AGENT_PW`.
- Local: `cd dashboard && npm run dev` for the React app. Tests:
  `cd runtime/app && python3 -m pytest tests/`. CLI:
  `python -m scrollantir.tools.run_deriver list|run`.
- Deploy a runtime change: `rsync -avz runtime/app/src/
  orch:/tmp/scrollantir-src-new/ && ssh orch 'sudo rsync -a --delete
  /tmp/scrollantir-src-new/ /opt/scrollantir/repo/runtime/app/src/
  && cd /opt/scrollantir/repo/runtime && sudo docker compose build
  agent && sudo docker compose up -d --no-deps agent'`. **Always
  exclude `.env`** with `--exclude=".env"` on the second rsync.
- Apply a migration: `awk '/^-- migrate:down/{exit} {print}'
  runtime/db/migrations/NNNN_*.sql | ssh orch "sudo docker exec -i
  scrollantir-postgres-1 psql -U scrollantir -d scrollantir
  --single-transaction -v ON_ERROR_STOP=1"`.
- Mapbox token plumbing: never read `dashboard/.env.local`
  contents directly. Pipe through `ssh + sudo tee` so the value
  never enters your context.
